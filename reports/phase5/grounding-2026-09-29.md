## NOTCAM false-abstention incident, 2026-09-30

The user-reported `what is NOTCAM?` failure was reproduced against the live API. Retrieval supplied `instruments-notcam-overview-html.md`, and Command R generated the correct definition with a supplied citation. Validation rejected it because the source used micro sign `µ` (U+00B5) while the model used equivalent Greek mu `μ` (U+03BC). The earlier Phase 5 smoke set had missed this regression.

Quote, content-token, and unit comparisons now canonicalize those two glyphs and Unicode composed characters. Broad compatibility normalization is deliberately avoided so exponents and case-sensitive commands retain their meaning. A further live NOTCAM capabilities failure exposed concatenated HTML list boundaries (`.../pixel)- High...`): inserting line breaks is now accepted at those specific list boundaries. Changed numerical values and changed units are still rejected, including when the model supplies a correct quote but alters its claim.

The live wavelength question also omitted the overview from selected context and instead retrieved an old design PDF with damaged unit text and filter-band tables. Explicit instrument definition, capability, and wavelength-range questions now retrieve matching overview files into the candidate pool, retain the similarity threshold, and prefer active authoritative/reference overviews. Technical procedure questions keep their existing retrieval policy. The prompt also requests complete subject-bearing claims rather than unexplained numeric lists.

Regression fixtures cover the original NOTCAM quote, repaired list layout, altered values/units, preserved superscripts and commands, and targeted overview ranking. The reproducible live check is `python3 scripts/evaluation/smoke_core_instruments.py`; it checks NOTCAM definition variants, capabilities, wavelength range, ALFOSC, FIES, and an unsupported-question control. Historical commissioning/gallery material mislabeled active is tracked separately as B-006 in the implementation plan.

The expanded checks also caught model-added acronym expansions and malformed extra quotes. Rejected nonempty claim output now gets at most one correction request using the same evidence and validation rules. Deliberate empty-claims abstentions do not retry. Both outputs are retained in the encrypted audit, and trace/token/latency totals account for both attempts. Three mocked service tests verify successful correction, deliberate abstention, and stopping after an unsuccessful correction. The prompt explicitly requests supported activities for capability questions instead of merely repeating an instrument definition.

The Phase 4/5 fixture suite passes 24 tests, and the API-container Python environment passes three additional service tests. This incident confirms that fixture precision alone cannot substitute for representative live answer-availability and completeness checks; those core-instrument cases must remain in the Phase 6 suite.

Final live results: all seven cases passed with `command-r:35b` and prompt contract `phase5-structured-v2`; see `core-instrument-smoke-2026-09-30-validated.json`. Both NOTCAM definitions and the capabilities answer cited the overview on their first attempt. The wavelength answer returned `0.8 to 2.5 micrometres` after one correction (54,810 ms total). ALFOSC and FIES also answered with supplied citations; the unsupported control abstained before generation. Equivalent unit symbols and spelled-out metre/meter forms are checked consistently, with regression tests rejecting substitution of millimetres for micrometres. Intermediate failing runs are retained to document the progression; the validated JSON is the final result.

## Lost-context follow-up and checked inference, 2026-09-30

The encrypted audit confirmed that the failed `can the instrument be used to observer at 500nm?` request contained the preceding NOTCAM user question and answer. The frontend had sent history correctly. Retrieval embedded and classified only the latest message, however, and supplied LuckyCam, FIES, and generic observing/detector chunks. The model still named NOTCAM but cited unrelated evidence; validation correctly rejected that output. A model change would not fix the missing retrieval subject.

With prompt version `phase5-structured-v3`, narrow instrument pronouns and short follow-ups now resolve against recent user turns before embedding, classification, overview lookup, and reranking. Explicit instrument names override history. A recent multi-instrument subject requires clarification, and a new unrelated user topic stops inheritance. Assistant answers and old citations do not become evidence; factual support always comes from newly retrieved documents. The bounded history still limits how far back the subject can be recovered. General non-instrument coreference remains a Phase 6 evaluation/implementation boundary.

The ordinary claim validator continues rejecting unsupported numbers, units, and negations. A separate narrow checked-reasoning path now converts a single requested wavelength using Decimal arithmetic and compares it to an instrument-wide interval in supplied current tier-1/tier-2 evidence. It requires an explicit matching source subject, rejects conflicting intervals and historical/unreviewed/accessory/design ranges, and declines complex mode/filter questions. It does not hard-code NOTCAM's limits or the user's wavelength. Below/above values yield a cited negative conclusion; in-range values establish only range membership, not availability of a specific filter/mode. The derivation, exact source sentence, resolved retrieval query, and original history remain in the encrypted audit. Public trace identifies context resolution and answer method, and correctly reports zero model requests/tokens on the checked path.

The initial eight-case run passed, but repeating it exposed an intermittent `Which wavelength range does it cover?` failure. Retrieval supplied the right overview; the model added a damaged design-PDF quote on its first attempt and used a correct range quote with insufficient lexical overlap on correction. This 7/8 run is retained as `followup-context-2026-09-30-intermediate.json`. We did not lower citation or overlap requirements globally. Explicit simple range queries now use the same checked interval extraction as comparisons, without generated paraphrases or extra claims.

`python3 -m unittest scripts.tests.test_followup_phase5 scripts.tests.test_grounding_phase5 scripts.tests.test_chat_audit_phase5 scripts.tests.test_retrieval_phase4 -v` passes 39 fixtures; seven mocked service tests pass in the API Python environment (46 total). `scripts/evaluation/smoke_followup_context.py` passes all eight live checks: NOTCAM definition, the exact 500nm follow-up, chained 1000nm follow-up, 3000nm follow-up, explicit 500nm question, checked follow-up wavelength range, explicit switch to FIES, and ambiguous-subject clarification. See `followup-context-2026-09-30.json`. The exact reported follow-up returns the NOTCAM overview citation and `No. 500nm (= 0.5 µm) is below NOTCAM's documented wavelength range (0.8–2.5 µm)` without model generation (27ms in the initial run). This is a scoped bug fix, not completion of Phase 6 or a claim that arbitrary scientific reasoning is now supported.
